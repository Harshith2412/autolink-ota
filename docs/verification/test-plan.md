# Test plan

## Levels

| Level | Scope | Tool | Location | Run |
|---|---|---|---|---|
| Unit (C++) | state machine, versions, crypto, manifest policy, persistence, agent behaviour, power loss via fork | GoogleTest API (bundled harness offline) | `ecu/tests/ecu_tests.cpp` | `make test-ecu` |
| Unit/API (Python) | validation, auth, RBAC, firmware verification, campaigns, device protocol, idempotency | unittest (pytest-compatible) + Flask test client | `backend/tests/test_api.py` | `make test-backend` |
| Unit (TypeScript) | lifecycle-rail mapping | node:test via tsx | `frontend/tests/unit/` | `make test-frontend` |
| Integration | real backend process + compiled ECU over HTTP | unittest + `experiments/runner/stack.py` | `tests/integration/test_end_to_end.py` | `make test-integration` |
| End-to-end | above plus dashboard in headless Chromium | Playwright library | `tests/integration/test_dashboard_e2e.py`, `frontend/tests/e2e/` | `make test-e2e` |
| Fault injection | 25 scenarios × 7 seeds | `run_matrix.py` | `experiments/` | `make experiments` |

All levels use deterministic inputs: fixture keys from fixed seeds, Ed25519's deterministic signatures, seeded
RNGs for fault timing, and simulated telemetry derived from a tick counter.

## Entry and exit criteria

Entry: ECU builds with `-Wall -Wextra -Wpedantic -Werror`; migrations apply to an empty database.
Exit for a release: every suite passes, the fault matrix shows zero consistency violations and every scenario
meets its expected outcome, and `docs/verification/*` are regenerated by `scripts/collect_evidence.py`.

## Required end-to-end scenario (brief §10)

`IT001` and `IT010` start the stack, register a vehicle, upload a signed package, create and approve a
deployment, run the update on the ECU binary, check the ECU's final slot and version, check backend records
(deployment events in order, vehicle version, telemetry), and confirm the dashboard displays the result.
`IT002`/`IT010` do the same with a corrupted image that the ECU must reject.

## Mutation checks

The suites were confirmed to detect three injected defects (see `test-results.md`). Re-run after significant
refactoring of verification, idempotency or authorization code.

## Not tested

TLS, MQTT, PostgreSQL, Docker images, Terraform, CI workflow execution, concurrent multi-vehicle load, the CMake
build, TypeScript type-checking, viewer-role dashboard behaviour, dashboard empty states and dialogs in a browser.
